# Study Studio Pro — architecture decisions

1. **One engine.** `studio-ink.js` owns tool state, pointer handling, rendering, history, persistence and export. `studio-core.js` is pure logic (no DOM) so it is unit tested in Node (`tests/studio_core_check.cjs`). Tools (`studio-tools.js`, `studio-smart.js`) register with `MedixaStudio.registerTool`; there is no second listener chain or second store.
2. **Canonical coordinates.** Stroke points are (u,v) of the *upright page as pdf.js shows it* (after /Rotate and CropBox), origin top-left. DPR only changes raster resolution; zoom only changes CSS size. Margins extend the domain to u∈[-l,1+r], v∈[-t,1+b] without moving existing points. `viewToPdf` maps to PDF user space and was checked against pdf.js output for rotations 0/90/180/270 and a CropBox.
3. **Compatibility.** The v1 stroke shape and the storage key are unchanged; v2 fields are additive. Legacy data is migrated in memory with deterministic ids and is only rewritten on the first real edit; malformed entries are kept verbatim. The old reader can still read v2 data (unknown tools degrade to a polyline).
4. **No new libraries/servers.** Still static HTML/JS, pdf.js 3.11.174 and pdf-lib 1.17.1 from the existing CDN pins. Nothing is sent anywhere (checked in studio_phase4_browser).
5. **Lazy reader.** All sections exist up front with exact sizes; canvases (page, ink and offscreen cache) are rendered only near the viewport and released beyond a bound of 12 pages.
6. **Virtual pages.** Source pages keep their own number as id forever; blank pages use ids ≥ 100001 and are *not* `.page`, so older modules that index `.page` keep seeing source pages only. Notebooks are documents with no source pages.
7. **Tabs by navigation, not by live iframes.** Each document has its own store, history (sessionStorage), position and dirty marker; switching flushes first. Split view's second pane is an iframe because it must be live next to the first.
8. **Existing study stores are reused.** Cards/questions go through `MedixaStudyStore` (exposed by the existing inline study script) so the panel's guard, conflict detection and scheduler fields stay authoritative.
