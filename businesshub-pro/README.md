# BusinessHub Pro — المرحلة 1

تطبيق سطح مكتب (Electron) **محلي بالكامل** لإدارة 10–30 نشاطاً تجارياً: حساباتها الاجتماعية (إنستغرام، فيسبوك، واتساب للأعمال، تيك توك)، وحساباتها الإعلانية، وملفات متصفح بجلسات معزولة ودائمة. الواجهة عربية RTL بتصميم داكن.

> المرحلة 1 لا تتصل بأي API رسمي. تكاملات Meta وTikTok وWhatsApp موجودة كهياكل «غير متصل» فقط.

## المتطلبات والتشغيل

```bash
cd businesshub-pro
npm install          # postinstall ينزّل better-sqlite3 المبني مسبقاً لإصدار Electron (scripts/native.mjs)
npm run build        # typecheck + بناء الواجهة (Vite) + بناء العملية الرئيسية (esbuild)
npm start            # يبني ثم يشغّل التطبيق
npm run dev          # وضع التطوير (Vite + Electron)
```

الاختبارات والفحوص:

```bash
npm run typecheck
npm run lint
npm test             # unit + isolation (مرحلتان) + smoke
npm run test:unit | test:isolation | test:smoke
```

على لينكس بلا شاشة تُشغَّل اختبارات Electron تلقائياً عبر `xvfb-run` وبـ `--no-sandbox` (الحاوية تعمل كـ root). على ويندوز تعمل مباشرة.

تحزيم ويندوز:

```bash
npm run dist         # NSIS installer في مجلد release/ (ثم يستعيد better-sqlite3 للجهاز الحالي)
```

> إصدار Electron مثبّت على **42.x** عمداً: `better-sqlite3` 12.11 يوفّر ملفات مبنية مسبقاً حتى ABI 146 فقط؛ إصدارات Electron الأحدث تحتاج بناءً من المصدر (أدوات البناء + اتصال بـ electronjs.org). إن غيّرت الإصدار شغّل `npm run rebuild:native`.

## بنية المشروع

```
src/shared/contract.ts   مخططات Zod + أنواع الكيانات + قائمة قنوات IPC (مصدر الحقيقة الوحيد)
src/main/store.ts        SQLite (better-sqlite3)، هجرات بإصدار، نسخ احتياطي/استعادة، فحص سلامة
src/main/services.ts     منطق الأنشطة والحسابات والبروكسيات والملفات والإعلانات والتقارير
src/main/browser.ts      تشغيل/إغلاق نوافذ الملفات (persist:profile-<uuid>)، البروكسي، الصلاحيات
src/main/ipc.ts          تسجيل القنوات المسموحة فقط + تحقق Zod لكل مدخل
src/main/integrations.ts هياكل للقراءة فقط: Meta / TikTok / WhatsApp = not_connected
src/preload/             جسر ضيق (call + onRunningChanged)؛ شريط عنوان نافذة الملف
src/renderer/            React + Tailwind (عربي RTL)
```

## الميزات العاملة فعلاً (مُختبَرة آلياً)

- **النظرة العامة**: أعداد حقيقية من SQLite (أنشطة، حسابات، ملفات، إعلانية، حملات، بروكسيات)، بطاقات الأنشطة، آخر الملفات فتحاً، حالة التكاملات.
- **الأنشطة**: إنشاء/تعديل/حذف، بحث، تصفية (الفئة/الحالة)، عرض شبكة/قائمة، أرشفة وإلغاء أرشفة.
- **تفاصيل النشاط**: أربعة تبويبات للمنصات بحساباتها، ملفات المتصفح، الحسابات الإعلانية، وقسم الحملات الموسوم «غير متصل».
- **الحسابات الاجتماعية**: CRUD وبحث وتصفية (المنصة/النشاط). لا يُطلب ولا يُخزَّن أي كلمة مرور لأي منصة.
- **ملفات المتصفح**: CRUD، تشغيل/إغلاق، حالة «يعمل/متوقف»، آخر فتح، صفحة رئيسية لكل ملف، بروكسي اختياري، **نسخ البيانات الوصفية فقط** (جلسة جديدة فارغة)، **فتح رابط خارجي داخل ملف محدد** (بعد التحقق من http/https).
- **جلسات معزولة ودائمة**: لكل ملف `partitionId` ثابت (يمنع تعديله trigger في القاعدة) والجلسة `persist:profile-<uuid>`؛ كوكيز وlocalStorage وIndexedDB منفصلة وتبقى بعد إعادة تشغيل التطبيق.
- **البروكسيات**: http / https / socks5. مصادقة http/https تعمل عبر حدث `login` (مُختبَرة ببروكسي محلي حقيقي يرد 407، مع حد 3 محاولات). كلمة المرور مشفّرة بـ `safeStorage` في جدول `proxy_secrets` المنفصل ولا تصل للواجهة ولا للسجلات.
- **الحسابات الإعلانية**: سجلات محلية، تُنشأ دائماً `not_connected`؛ زر «ربط مزوّد» معطّل مع توضيح.
- **التقارير**: ملخصات محسوبة من بياناتك فقط (حسب الفئة/المنصة/المزوّد). لا إنفاق ولا أداء إعلاني.
- **الإعدادات**: معلومات التطبيق ومجلد البيانات، نسخ احتياطي (`db.backup` + فحص سلامة)، استعادة (تحقق ← نسخة تلقائية من الحالية ← استبدال)، حالة تشفير النظام، سجل التدقيق، بيانات تجريبية **اختيارية** (30 نشاطاً و120 حساباً بالبادئة «[تجريبي]» وتُحذف بزر واحد).
- **حدود الخطأ**: `ErrorBoundary` لكل صفحة، وسجل تدقيق بيانات وصفية منظّفة (يحذف أي مفتاح يشبه password/secret/token).

## سياسة حذف النشاط

حذف نشاط **متسلسل (CASCADE)** ويتطلب كتابة اسمه حرفياً للتأكيد (يُتحقق منه في العملية الرئيسية أيضاً). يُحذف معه: حساباته الاجتماعية، ملفات المتصفح **مع مسح بيانات جلساتها**، حساباته الإعلانية وحملاتها. **لا يُحذف**: البروكسيات المشتركة وسجل التدقيق. الأرشفة هي البديل الآمن. حذف حساب اجتماعي يُبقي ملفاته بلا ربط؛ حذف بروكسي يجعل ملفاته مباشرة.

## القيود الأمنية والحدود المعلنة

- **عزل الجلسات ليس إخفاءً للبصمة** ولا ضماناً لتجاوز كشف المنصات. البرنامج يستخدم Chromium المثبّت مع Electron بلا تعديل، ولا يقدّم تزييف بصمات ولا تجاوز CAPTCHA ولا تفاعلاً/إبلاغاً جماعياً.
- **SOCKS5 بالمصادقة غير مدعوم** في Chromium؛ يرفضه البرنامج صراحة بدل ادّعاء نجاحه.
- **تشفير الأسرار** يعتمد على `safeStorage` (DPAPI على ويندوز). إن لم يكن متاحاً (مثل لينكس بلا keyring) **يرفض البرنامج حفظ أي كلمة مرور بروكسي** ويعرض ذلك في الإعدادات ونموذج البروكسي.
- النسخة الاحتياطية تشمل قاعدة البيانات فقط: **لا تشمل كوكيز/جلسات المتصفح**، وأسرار البروكسي المشفّرة مرتبطة بحساب ويندوز والجهاز فلا تُفك على جهاز آخر (أعد إدخالها).
- `contextIsolation` مفعّل، `nodeIntegration` معطّل، `sandbox` مفعّل لكل النوافذ؛ صفحات الويب بلا preload؛ التنقل والنوافذ المنبثقة مقيّدة بـ http/https؛ صلاحيات الجهاز (كاميرا، موقع، إشعارات…) مرفوضة افتراضياً؛ CSP صارم لصفحة اللوحة.
- شعار النشاط `logoPath` موجود في المخطط لكن لا واجهة له في المرحلة 1.

## ما اختُبر وما لم يُختبر

اختُبر هنا (لينكس + Xvfb، Electron 42.11 / Chromium، SQLite 3.53): وحدة البيانات (66 فحصاً)، العزل والاستمرارية بعد إعادة تشغيل حقيقية والبروكسي (23 فحصاً)، الواجهة الكاملة عبر IPC (34 فحصاً)، typecheck، lint، البناء، إقلاع `electron .`، وتحزيم `win-unpacked` (ملف better-sqlite3 بصيغة PE32+ لويندوز).

**لم يُشغَّل على ويندوز فعلي**، ولم يُبنَ مثبّت NSIS ولا تم توقيعه، ولم يُجرَّب DPAPI الحقيقي (الاختبارات تستخدم صندوق AES تجريبياً بدل `safeStorage` لأن لينكس بلا keyring).
